# Spec: Fehler aus der heytcass-Fork-Sichtung, Bilder aufräumen (3.2.0)

Stand: 2026-10-09 · Ziel-Version: 3.2.0 (neue Option) · Status: Entwurf im Chat bestätigt
Quelle: Sichtung aller 104 Forks von heytcass/home-assistant-addons am 2026-10-09
(58 mit eigenen Commits, 1.092 Commits am Claude-Add-on). Die Befunde unten sind
gegen unseren Code geprüft (Datei:Zeile auf `main` = `e8868d1`).

## Probleme

1. **Health-Check bricht beim ersten Fehler ab.** `scripts/health-check.sh:158-163`
   zählt mit `check || ((errors++))`. Bei `errors=0` ist der Wert des Ausdrucks 0,
   `(( ))` liefert Status 1, und bashios errexit beendet das Skript. Die übrigen
   Checks und die Zusammenfassung fehlen. `run.sh:797` fängt den Abbruch ab, der
   Start läuft weiter, die Diagnose ist aber unvollständig (owine `12316e4a`
   beschreibt dasselbe).
2. **Panel erst nach den langsamen Startschritten erreichbar.** Der Bild-Service
   (Port 7680, Ingress-Ziel) startet erst in `start_web_terminal` (`run.sh:759`),
   also nach `setup_persistent_claude` (Claude-Update) und
   `setup_persistent_packages` (`run.sh:811-815`). Auf HA-Prod am 2026-10-09:
   Start 09:19:12, Bild-Service 09:19:35 — 23 s, in denen HA nur 502 zeigt; mit
   vielen Paketen oder langsamem Netz Minuten.
3. **Upload-Dateiendung kommt ungeprüft vom Client.** `image-service/server.js:42`:
   `path.extname(file.originalname)`. Aus `x.png;touch $(id) #` wird die Endung
   `.png;touch $(id) #`. Der zurückgegebene Pfad wird im Browser per `term.paste()`
   ins Terminal eingefügt. Ein abgelehnter Dateityp endet als 500 statt 400
   (`server.js:146-151`).
4. **Mitgelieferte Skills/Commands kommen bei bestehenden Installationen nie an.**
   `run.sh:179-185` kopiert `/opt/.claude` nur, wenn `$HOME/.claude` noch nicht
   existiert. Jede Installation behält den Stand ihrer Erstinstallation.
5. **Auth-Helper hinterlässt den Code im Klartext.** `scripts/claude-auth-helper.sh:36`
   schreibt den Code nach `/tmp/claude-auth-code`; gelesen wird die Datei nie.
   `/config/auth-code.txt` wird erst nach dem Claude-Aufruf gelöscht (`:65`).
6. **Hochgeladene Bilder wachsen unbegrenzt.** `/data/images` wird nie aufgeräumt
   und liegt in jedem Backup der App.

## Entscheidungen

| # | Entscheidung | Verworfen |
|---|---|---|
| 1 | `\|\| errors=$((errors + 1))` – eine Zuweisung liefert nie einen Fehlerstatus | `set +e` im Skript (verdeckt echte Fehler) |
| 2 | `main()` startet den Bild-Service direkt nach `init_environment`; tmux und ttyd bleiben am Ende. `/terminal/` liefert, solange ttyd nicht antwortet, statt „Failed to connect to terminal“ (502) eine Startseite (503, „Claude Workbench is starting…“, Neuladen alle 3 s). WebSocket-Anfragen werden wie bisher beendet | Nur Reihenfolge ändern (Panel zeigt dann den 502-Text im iframe und bleibt dort) |
| 3 | Endung aus dem erlaubten MIME-Typ (`image/jpeg`→`.jpg`, `image/png`→`.png`, `image/gif`→`.gif`, `image/webp`→`.webp`, `image/svg+xml`→`.svg`); Name `pasted-<ms>-<8 Hex>.<ext>`; abgelehnter Typ → 400 | Endung des Clients filtern (Blockliste lückenhaft) |
| 4 | Bei jedem Start genau die Dateien aus `/opt/.claude` über `$HOME/.claude` kopieren (überschreiben); alles andere dort bleibt unberührt. Satz in DOCS: eigene Varianten unter eigenem Namen ablegen | Nur fehlende Dateien ergänzen (`cp -n`, Doku veraltet); Marker-Datei je Version (mehr Logik, gleiche Wirkung) |
| 5 | Temp-Datei entfällt; `/config/auth-code.txt` wird gelesen und **vor** dem Claude-Aufruf gelöscht. Pfad per `CLAUDE_AUTH_CODE_FILE` überschreibbar (nur für Tests). Verhalten sonst unverändert | Helper entfernen (ohne Beleg, dass er nicht funktioniert) |
| 6 | Neue Option `image_retention_days`, Typ `int(0,)`, Standard 30, 0 = nichts löschen. `prune_uploaded_images` in `run.sh` beim Start: löscht in `/data/images` nur reguläre Dateien `pasted-*`, älter als N Tage; Anzahl ins Log. Leerer, nicht ganzzahliger oder unlesbarer Wert → nichts löschen | Größengrenze (mattbsea, 200 MB: Zeitpunkt unvorhersehbar); täglicher Lauf im Node-Service (mehr Code, Uploads selten); feste Frist ohne Option (nicht abschaltbar) |

Version 3.2.0, weil Punkt 6 eine neue Option ist (Projektregel: neue Features = Minor).

## Nicht dabei

- `persist-install` kopiert keine apk-Dateien (`apk info -L` liefert relative Pfade,
  `scripts/persist-install:104-106` vergleicht mit `/usr/bin/*`) – gehört zum
  zurückgestellten Folgepunkt 7 (Paket-Persistenz).
- Weitere Fork-Ideen (`claude_extra_args`, `~/.tmux.conf.local`, Mobil-Toolbar,
  `working_directory`, `map: share/addons`, `permissions.deny`, Shift+Enter,
  Auto-Continue, ripgrep) und die heytcass-Reste (Boot-Smoke-Test, Health-Check
  mit `claude --version`, Sicherheits-Doku) – eigenes Release.
- Ingress-IP-Filter (nur `172.30.32.2` an Port 7680), `watchdog:`.
- Entfernen des Auth-Helpers; `backup_exclude` für `/data/images`.

## Offene Frage (ohne Umsetzung in 3.2.0)

Ob `echo "$code" | claude` im Auth-Helper den Login überhaupt durchführt, ist nicht
belegt (Vermutung: Claude Code startet mit umgeleiteter Eingabe nicht interaktiv
und behandelt den Code als Prompt). Beim HA-Test einmal ausprobieren; scheitert es,
Menüpunkt und Skript in einem späteren Release entfernen.

## Tests (TDD, je zuerst rot)

1. Neue Suite `tests/test-health-check.sh`: `health-check.sh` unter errexit, errtrace,
   nounset, pipefail laden; zwei Checks per Stub scheitern lassen → alle Checks
   laufen, Ausgabe enthält „2 check(s) failed“.
2. Strukturtest (in `tests/test-startup-hardening.sh` oder neuer Suite):
   in `main()` steht `start_image_service` nach `init_environment` und vor
   `setup_persistent_claude`; `start_web_terminal` ruft es nicht mehr auf.
   `tests/test-image-service.js`: `GET /terminal/` ohne ttyd → 503, HTML mit
   `http-equiv="refresh"`. Der vorhandene Test „/terminal answers 502 when ttyd is
   not reachable“ (`tests/test-image-service.js:324`) wird bewusst darauf umgestellt.
3. `tests/test-image-service.js`: Upload mit Dateiname `x.png;touch $(id) #` und Typ
   `image/png` → `filename` passt auf `^pasted-\d+-[0-9a-f]{8}\.png$`;
   Typ `text/plain` → 400.
4. Bash-Test: vorhandenes `$HOME/.claude` mit veralteter Skill-Datei, eigener Datei
   und Credential-Datei → Skill-Datei gleich der Image-Datei, die anderen unverändert.
5. Bash-Test: Helper mit Eingabe „2“, `CLAUDE_AUTH_CODE_FILE` auf eine Testdatei,
   Stub-`claude` im PATH protokolliert, ob die Datei beim Aufruf noch existiert →
   existiert nicht; `/tmp/claude-auth-code` bzw. kein Temp-Rest entsteht
   (statische Prüfung: kein Schreibzugriff auf `/tmp/claude-auth-code` im Skript).
6. Bash-Test für `prune_uploaded_images`: alte und neue `pasted-*`, fremde alte Datei,
   Unterordner → nur die alte `pasted-*` weg; Werte `0`, leer, `abc`, `-1` löschen
   nichts. `tests/test-release-metadata.sh` verlangt die Option mit Übersetzung en/de
   (vorhandene Regel „jede Option übersetzt“).

Suiten, die neu dazukommen, in `tests/run-tests.sh` und `.github/workflows/ci.yml`
eintragen; ShellCheck wie die CI.

## Ende-zu-Ende-Kriterium (HA-Test nach dem Update)

- App-Log: „Image service is healthy“ steht vor „Persistent Claude override: updating“.
- Panel während des Starts öffnen → Startseite, danach von selbst das Terminal.
- Vorher `touch -d '40 days ago' /data/images/pasted-old.png` und
  `touch /data/images/pasted-new.png` (User) → nach dem Neustart alte weg, neue da,
  Logzeile mit Anzahl.
- Bild einfügen funktioniert; Dateiname im neuen Format.
- Health-Check-Zusammenfassung im Log.
- `cmp /opt/.claude/skills/persistent-package-manager/SKILL.md
  ~/.claude/skills/persistent-package-manager/SKILL.md` ohne Ausgabe.
- Danach HA-Prod (User startet das Update), Logs per MCP.
